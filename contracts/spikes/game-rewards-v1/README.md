# Game rewards contract spike (G7e, research only)

Answers the open questions in ADR-018 Amendment 3 by running a real contract through the
Alkanes indexer harness (`alkanes-rs` revision `62511e9371a3f9e448841140c51cfe428cfcb955`, the
same pin as the allowlist spike). It is not a deployable template: no admin, pause, retire or
audit, and it has not been mutation-tested.

- `game-rewards/`: opcode 0 initialise (collectible template id, per-wallet limit), 1 claim
  (milestone), 99 name, 100 claimed count by holder and milestone.
- `collectible/`: one collectible, supply one, opcodes 0, 99, 100, 101 and 1000 (`get-data`).
- `harness/tests/claim.rs`: five tests through `index_block`, the mainnet code path.

Run: `cargo build --release --target wasm32-unknown-unknown -p milestone-collectible -p game-rewards`
then `cd harness && cargo test --test claim` (needs `wasm-bindgen-test-runner` 0.2.100). It is its own
workspace; `Cargo.lock` is the pinned `alkanes-rs` lock, because newer crates need Rust above 1.86.

## What the runs showed

| Question                                              | Answer                                                                                                                                                                                                                                                                                                         |
| ----------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Can a game contract create a collectible per claim?   | Yes. `call` to `{6, template}` creates a new instance of a template deployed at `{3, template}`; the new alkane id comes from the sequence (`{2, n}`). Each claim is one small transaction, no code is shipped with it.                                                                                        |
| Is the content readable through `get-data`?           | Yes. `view::call_view(id, [1000])` returns the payload (`{"milestone":7,"serial":1}`).                                                                                                                                                                                                                         |
| Where does the content live?                          | In indexer state, derived by the template from the claim's inputs. Only the call crosses Bitcoin, so "light content" is code in the template plus those inputs, not inscribed bytes. Anything larger needs a reference (a hash or a URL) or art generated by the template.                                     |
| Is the per-wallet limit enforceable?                  | Yes, per (holder, milestone). The third claim reverts with `claim limit reached`; a different milestone has its own count.                                                                                                                                                                                     |
| Can we read the count for the `rewards.claimed` port? | Yes, with opcode 100 and the holder as the SHA-256 of its output script split into two u128 halves.                                                                                                                                                                                                            |
| Who is the claimant?                                  | Only the script output 0 pays to. The runtime does not expose the outputs a transaction spends (`AlkaneResponder::output` is commented out upstream), so a contract cannot tell who signed an input. Someone can therefore claim for another wallet: the victim gets a free collectible and uses a claim slot. |
| Can tokens be transfer-locked?                        | No. A plain protostone edict moved the collectible to a new output without calling the contract (test 4).                                                                                                                                                                                                      |
| Template size                                         | `game-rewards` 247 KB (133 KB gzip), `collectible` 219 KB (123 KB gzip) after `opt-level z`, LTO; `wasm-opt -Oz` saves about 15%. Paid once per template, not per game.                                                                                                                                        |

## What this means for the adapter (ports in `@ador/chain`)

The contract is the only chain-specific part; the domain asks the same questions of any chain.

- `contracts` (deploy): publish the two templates once, then one `game-rewards` instance per game
  (`{6, template}`), initialised from the manifest `claimPolicy`.
- `builder` (claim): a transaction with a protostone calling the game's `claim(milestone)`, paying
  output 0 to the claimant's address. Another chain builds its own mint call from the same inputs.
- `broadcaster` / `observer`: unchanged; the observer maps the trace (`view::trace`) to confirmed
  or reverted, and the created collectible id to the claim.
- `rewards.claimed(contract, holder, milestone)`: opcode 100.
- Collectible preview: `get-data` (opcode 1000) through the family's reader.

## Open findings

1. Claimant binding is weaker than the allowlist spike's signed-input check. That check needs the
   spent outputs, which a contract cannot read; the transaction could carry them, but then they are
   unverified. Output 0 is acceptable for self-reported milestones (griefing costs the attacker a
   fee), and the host should show "claimed" only for the wallet the platform signed in.
2. No transfer lock; the ADR already accepts this.
3. Not done: admin (auth token, pause, retire), fuel cost of a claim, a claim from a real wallet,
   a collectible payload richer than a milestone id, `Cargo.lock` drift policy, and the build in CI.
